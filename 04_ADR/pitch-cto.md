# Pitch для CTO

---

Мы выбираем облачную LLM по API (класс GPT-5 / YandexGPT Pro), потому что в текущих условиях это единственное решение, которое одновременно проходит по трём жёстким ограничениям: экономике, качеству и срокам. На MVP-этапе наш трафик (~80M токенов/день с учётом агентных циклов) при blended-цене ~\$1.5/1M токенов стоит ~\$3.6K/мес с оплатой по факту, тогда как self-hosted Llama 3 70B требует ≥ $7.9K/мес фиксированных затрат (GPU 24/7 + MLOps) — и окупается только при стабильных ~175M токенов/день, т.е. при загрузке в 2.2 раза выше текущего прогноза; это ровно та ловушка, которую описывает a16z: собственный инференс выгоден только при высокой и стабильной утилизации, которой у нас пока нет. Единственный реальный аргумент против — приватность — закрыт архитектурно, а не обещаниями: DPA с Zero Data Retention, маскирование PII до промпта, RAG-контур внутри периметра, региональный endpoint; в данных уходит только обезличенный минимум. При этом качество флагманов в tool calling и структурированном выводе критично для нашего мультиагентного Supervisor'а, где одна ошибка планирования рушит весь сценарий, а Llama 3 70B на агентных бенчмарках стабильно уступает. Мы не запираем себя в вендоре: доступ через шлюз-абстракцию, квартальные миграционные тесты и зафиксированные триггеры (трафик > 100M токенов/день — ранний сигнал до порога безубыточности, утилизация GPU > 60%, регуляторные изменения) — при их срабатывании открываем новый ADR на миграцию чувствительных контуров на self-hosted. Решение даёт нам MVP за недели вместо месяцев, предсказуемый OPEX и сохраняет путь к отходу.
